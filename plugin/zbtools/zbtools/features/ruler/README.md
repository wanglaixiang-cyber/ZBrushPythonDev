# 功能:屏幕真尺

在屏幕上贴一把**物理真实刻度**的尺子(1 mm 就是屏幕上的 1 mm),可以任意角度摆放,
也可以同时摆好几把。模型以 1:1 显示后,把零件对到刻度上直接读长短。

## 交互(全部在浮层窗口里)

| 操作 | 效果 |
|---|---|
| 左键拖动 | 移动尺子 |
| 右键拖动 | 旋转:**抓左半边 → 以右端为轴;抓右半边 → 以左端(0 刻度)为轴** |
| 右键拖 + Shift | 角度吸附到 45° 的整数倍(覆盖 0/90/180/270) |
| 双击 | 删掉这把尺子(不记录位置) |
| 点尺身外空白 | 什么都不做(不会误抓/误旋转) |
| 鼠标移出尺身 | 立即**点击穿透**,不挡画布(容差 12 点 + 0.3 秒迟滞,避免点不中) |

尺子两面都有刻度:一面毫米(每 50 mm 红标),另一面英寸(1/16 小节)。

## 面板

```
[新建尺子] [删除尺子]
[尺长 mm] 滑块        # 20–500,默认 200;只影响之后新建的尺子
[诊断信息]        # 刻度依据 + 每把尺子的实时状态与切换历史
```

- **新建尺子**:再加一把(位置/角度接着上一把,自动错开)—— 不弹通知,只看屏幕
- **删除尺子**:删掉所有尺子;只想删某一把就在尺子上**双击**
- 尺子两面都有刻度:一面公制(每 50 mm 红标),一面英制(1/16 小节)

## 为什么是外部浮层窗口

- ZBrush 的 Python API **没有任何画布绘图能力**(没有画线/画矩形/画字),插件 UI 也只能
  待在左右面板或作为居中模态 Note(Note 的定位参数官方标注 "Has no effect")
- 真尺要能**旋转**,而窗口本身不能被旋转 —— 只能开一个比尺身大的透明窗口,在里面旋转绘制
- 于是窗口有一大片透明死区,必须做到「**鼠标不在尺子上时点击穿透**」(利用
  `setIgnoresMouseEvents_` + 后台线程查询光标位置;tkinter 做不到)
- 每把尺子 = 一个独立子进程;几何状态各写各的文件(`~/.zbtools_rulers/<id>.json`),
  所以多把尺子同时启动也不会互相覆盖

## 刻度依据(重要)

```
1 mm = 逻辑ppi ÷ 25.4 个逻辑点 = 3.1992 逻辑点 = 6.3984 原生像素(P270:81.26 逻辑ppi)
```

- 与「显示实际大小」用**同一套 ppi 口径**,不会各说各话
- EDID 的物理宽高只做**交叉核验**:按它算横竖会差 1.2%,而屏幕像素是方的,不能当基准
- 尺子因此与 ZBrush 画布缩放、模型、透视**无关**;反过来,**读数是否有意义取决于模型
  是否 1:1 显示**(那是「实际大小」功能的事)。平移视窗不改变比例,可以放心边移边量

## 核验

1. **实体尺子**:贴在屏幕上比 100 mm(最可信)
2. **自动核验**(差分法,不需要实体尺子):

```bash
.venv/bin/python scripts/verify_ruler_overlay.py 3.1992 --pid <尺子进程PID> --angle 30
```

实测结论:角度 0°/45°/137° 偏差 ≤0.02°,刻度周期误差 **0.15%**。

## 限制

- 浮层挡住的那一条区域点不到 ZBrush(尺子很薄;鼠标移开即点击穿透,不挡操作)
- 尺子不能斜着"卡"住画布边框,只能自己摆
- 依赖 `cfg["interpreter"]` 指向能跑 AppKit 的解释器(默认项目 venv)
