# 贴图转色(tex2pp)

低模(有 UV + 贴图)的**贴图颜色** → 高模(DynaMesh)的 **polypaint**。
**不用细分低模,也不用给高模做 UV。**

(想先把贴图变成**深度图**?那是另一个独立功能 `图片转深度图` —— 和这里的①②无关,见
`../depthimg/README.md`。)

## 进度反馈(ZBrush 顶部状态条)

① 导出低模、② 导出高模 + 烘焙,这两段"看不见的等待"都会喂给顶部状态条
(`ui.Progress`,节流 100ms;实测 ZBrush 回调里更新会自动刷新、等子进程期间也能刷新):

| 阶段 | 进度 | 怎么来的 |
|---|---|---|
| ② 导出高模(等 ZBrush 写盘) | 0 → 0.12 | `export_active(..., on_tick=)` 每 0.2 秒爬一次 |
| 读低模 / 读高模 | 0.12 → 0.22 | 管线日志映射 |
| **查询最近点(最慢一步)** | 0.22 → 0.82 | 管线**分块查询**并报 `[zbtools-progress]` 真进度 |
| 写 PLY / 读报告 | 0.82 → 0.95 | 管线日志映射 |
| 提交导入给 ZBrush | 0.95 → 清空 | — |

分块查询只为"能报进度",每个顶点的最近点互相独立,数值与一次性查询**完全一致**。
## 为什么不用 ZBrush 原生那条路

原生 `Tool > Polypaint > Polypaint From Texture` 是**逐顶点**采样贴图,官方文档因此要求
"把模型细分到接近贴图像素数"。低模只有几百个顶点时,它只能给出几百个颜色样本(色块)。

本功能把采样搬到**高模自己的顶点**上(DynaMesh 本来就有百万级顶点):

| | 原生路线 | 本功能 |
|---|---|---|
| 采样分辨率 | 低模顶点数(必须先细分) | **高模顶点数**(本来就有) |
| 给高模做 UV | — | 不需要 |
| 细分低模 | 必须 | 不需要 |
| 代价 | 内存/时间,且几何被改 | 一次外部烘焙(688k 顶点约 10 秒) |

## 用法(两步)

```
ZBTools
└── ---- 贴图转色 ----
      [① 记住低模    ] [UV 翻转     ]     ← 点中「有 UV + 贴图」那个低模再按①
      [② 烘焙并导回   ] [投射阈值 ▬▬▬ ]     ← 点中「高模 DynaMesh」那个再按②(默认 2%)
      [诊断信息                        ]
```

1. 点中**低模** → 按 **① 记住低模**:导出它、自动找到 ZBrush 顺手写出的贴图、记住
   (**同时只记一个**;再按一次就换成当前这个)
   * 导出走的是**临时文件名**,校验通过才落位 —— 所以万一选错模型(比如按在高模上),
     只报错、**不会把上一次记住的低模弄坏**
   * **模型没有 UV 会直接报错**:判据是"导出的 OBJ 里有没有 `vt` 行"
     (这是下游管线真正要吃的东西,比读 UV 框可靠)
2. 点中**高模** → 按 **② 烘焙并导回**:导出高模 → 外部按高模顶点采样贴图 →
   写 PLY → **直接导回**(变成 polypaint)

按钮都是普通按钮,状态只在**控制台 / 诊断信息**里说明 —— ZBrush 没有"选择变化"回调,
做成开关会停在旧状态,反而像 bug(踩过)。

| 控件 | 说明 |
|---|---|
| `UV 翻转` | OBJ 的 v 向上、图像行向下,默认翻转;导回后颜色**上下颠倒**时关掉再烘一次 |
| `投射阈值` | 最近点距离超过「包围盒对角线 × 此比例」的顶点记为"未被覆盖"(百分比,默认 2) |
| `诊断信息` | 解释器 / 依赖 / 路径 / 记住的是哪个模型 / 参数 / 工作目录,复制到剪贴板 |

**只有出错才弹提示**,成功一律只打控制台。

## 原理

```
ZBrush ① 低模 → Tool:Export → tex2pp_low.obj(+ 贴图:带 UV 的网格是 名.bmp + 名.mtl)
                                      │
       ② 高模 → Tool:Export → tex2pp_high.obj
                                      ↓
外部管线 tools/bake_pipeline.py(需要 numpy/trimesh/rtree/scipy/pillow)
   高模每顶点 → 低模表面最近点 → 该三角形重心坐标插值出 UV → 双线性采样贴图
              → 二进制 PLY(顶点 + 面 + uchar rgb,*逐面交错*)
                                      ↓
ZBrush ② Tool:Import ← tex2pp_polypaint.ply = polypaint
```

管线与插件**零耦合**:只吃命令行参数、只打 stdout、可选写 JSON 报告,可以单独跑:

```bash
.venv/bin/python plugin/zbtools/zbtools/features/tex2pp/tools/bake_pipeline.py \
    --low 低模.obj --high 高模.obj --texture 贴图.bmp --out 上色.ply --report-json 报告.json
```

## 实测结论(真机验证过的坑)

| # | 结论 | 影响 |
|---|---|---|
| 1 | **只有 PLY 顶点色能变成 polypaint**。OBJ 的 `#MRGB` 块 ZBrush **只写不读**,`v x y z r g b` 六分量顶点也不认 | 决定了整条链路走 PLY |
| 2 | 默认 GoZ 模板 `GoZ Binary.GoZ` **不含 `MRGB` 段**(只有 Complete / Cinema4D / WithMatcaps 有),`set_next_filename` 的 `template_path` 官方标注 "None-functional at the moment" | 所以 GoZ 这条"可能更快"的近路暂时走不通 |
| 3 | 导出/导入都靠 `set_next_filename(全路径)` + `press(...)`,而 **press 是命令队列**、不是同步调用 | 必须轮询"实际效果"(文件出现 / Tool 名变化) |
| 4 | `press` 偶尔漏出 CPython 的 `SystemError: ... returned a result with an exception set`,**此时命令其实已经进队列** | 报错降级为日志、按效果判定成败;只有效果没出现才真报错 |
| 5 | 导入**占用当前 Tool 槽**(不是追加 Subtool),Tool 名变 `!:/...`;PLY 由 ZScript 处理器逐点建网格,**很慢** | 提交后立刻把界面还给 ZBrush;导入期间界面会不响应几十秒起 |
| 6 | 导出的 OBJ 头有 `#Auto scale 0.1`,而 PLY 导入尺度与之一致(实测比例 1.000、点数与包围盒 1:1) | 不需要额外缩放;四边面拓扑也保住了(688,949 面) |
| 7 | PLY 的面数据必须**逐面交错**(`[顶点数][索引…]` 重复)。写成"先一整块顶点数、再一整块索引"时**文件总长度完全一样** | 尺寸校验与 trimesh 都看不出问题,但 ZBrush 报 `error -3` —— 已用测试钉死 |
| 8 | ZBrush 给**带 UV** 的网格导出的贴图是 **24 位 BMP**(透明通道被剥掉);无 UV 的写 `_TXTR.tif` | 要用 alpha 得自己先处理图(`tex2pp__texture_path` 可指定) |
| 9 | 面板控件的 `width` 是 **\|0,1] 相对宽度**(API 文档写"像素"是错的),官方建议显式写死 | 不写会被 ZBrush 排到一行里**重叠**;本功能用 `0.5 + 0.5` 一行两个 |
| 10 | 高位深贴图(16 位 TIFF/PNG)必须先归一到 0..255,**再**做 `convert("RGB")` | `convert` 会把 >255 直接裁掉,层次全丢(实测只剩 6 种颜色、一片近白) |

## 隐藏配置(不在面板上)

改 `plugin/zbtools/zbtools/settings.json`:

| 键 | 默认 | 用途 |
|---|---|---|
| `tex2pp__texture_path` | 空 | 换一张贴图(默认用模型带出的那张;**这个兜底层以前有 bug 没生效,现已修好**) |
| `tex2pp__triangulate` | `false` | 排障:PLY 里把面全三角化 |
| `tex2pp__alpha_only` | `false` | 把 alpha 当亮度源 → 黑白 polypaint(转遮罩用) |
| `tex2pp__aa` | `false` | 边缘抗锯齿(`aa_radius` / `aa_samples`,默认 1 像素 / 3x3) |
| `tex2pp__max_dist_ratio` | `0.02` | 同面板「投射阈值」 |
| `tex2pp__flip_v` | `true` | 同面板「UV 翻转」 |
| `tex2pp__keep_temp` | `true` | 关掉则每次 ① 前清空工作目录(默认保留 PLY 便于复查) |
| `tex2pp__io_wait_s` / `tex2pp__import_wait_s` | `300` / `1.5` | 等导出落盘 / 导入提交的最长秒数 |
| `tex2pp__work_dir` | 自动 | 工作目录;跨重启复用(见下) |

> `alpha_only` / `aa` 曾经在面板上,撤掉后**面板装配时会一次性把旧值清回默认**
> (`tex2pp__migrated_hidden_switches` 标记),免得留下看不出来由的隐藏行为。

## 排障

| 症状 | 原因 | 处理 |
|---|---|---|
| 提示 "press … returned a result with an exception set" | ZBrush 的 C 扩展漏异常,**命令已进队列** | 看结果;带"可忽略"就是效果已成立 |
| ② 是灰的 | 没记住低模,或工作目录里的导出文件被清理了 | 按 ① 重新记住 |
| ② 报"当前选中的就是被记住的那个低模" | 忘了切回高模 | 先点中高模再按 ② |
| 导回后颜色上下颠倒 | UV 的 v 轴方向相反 | 关掉「UV 翻转」再烘一次 |
| 大片区域颜色不对 | 低模与高模形状差太多,最近点跑到别的部位 | 看诊断的「未被覆盖」比例,或调大「投射阈值」 |
| 提示"找不到低模的贴图" | 那个 SubTool 没挂贴图,或导出没写出 | 确认低模真的挂了贴图,再按 ① |
| 报错"这个模型**没有 UV**,不能当低模" | 选错模型了(把高模当低模);导出的 OBJ 里没有 `vt` 行 | 点中**带 UV + 贴图**的那个模型再按 ①;上次记住的低模不受影响 |
| 导入后界面卡几十秒 | PLY 由 ZScript 处理器逐点建网格 | 正常;脚本已把界面尽早还给 ZBrush |
| 颜色层次丢失/整体偏白 | 贴图是高位深(16 位) | 已自动归一;若仍异常把诊断发我 |

工作目录(所有中间文件)会**写进配置并跨重启复用**:系统 temp 会被清理,路径失效时插件会
退回工作目录里的 `tex2pp_low.obj` 并自动修好配置(否则 ② 会因为"找不到低模"而灰掉)。

## 限制

- 高模必须与低模**形状大致重合**(DynaMesh 出来的高模最理想);差得远时"未被覆盖"比例会升高
- 颜色分辨率受**贴图分辨率**限制(2K 贴图 ≈ 400 万色样本),与高模顶点数无关
- 外部管线需要一台装了 `numpy / trimesh / rtree / scipy / pillow` 的 Python
  (开发态是项目 `.venv`;ZBrush 自带解释器没有这些库)。缺库时会给出安装命令
- 烘焙管线发行包里是 `.pyc`,外部解释器的**主版本要与打包时一致**
- 导入占用当前 Tool 槽:想并回原来的多 SubTool 工具,用 `Morph Target` + `Project All`
  (几何回滚、只留颜色)

## 文件

| 文件 | 作用 |
|---|---|
| `__init__.py` | 面板:两个按钮 + 两个参数 + 诊断 |
| `service.py` | ZBrush 侧:导出、找贴图、调外部管线、导回、诊断 |
| `tools/bake_pipeline.py` | 外部管线(零耦合,可单独跑) |
| `tests/test_tex2pp.py` | 算法(与暴力参考对照)+ PLY 结构 + 插件契约 + 真子进程 CLI 契约 + 隐患防护 |

> 导出/找贴图/按界面项这些**跨功能共用**的 ZBrush 操作在 `zbtools/zbapi/toolio.py`
> (「图片转深度图」功能也用同一份)。
